# Платформа развития критического и инженерного мышления

Веб-платформа для учеников 9 класса: 34 темы, по две задачи в каждой и ИИ-наставник, который ведёт ученика вопросами. Проект для диссертации.


## Переменные окружения

1. Скопируйте шаблон: `cp .env.example .env.local`.
2. Заполните значения. Файл `.env.local` не попадает в репозиторий.

Ключи `ANTHROPIC_API_KEY` и `SUPABASE_SERVICE_ROLE_KEY` используются только на сервере.

## Подготовка (этап 1, вручную)

- [ ] Создать проект в Supabase (регион в Европе), записать URL, anon-ключ и service_role-ключ в `.env.local`.
- [ ] В консоли Anthropic создать отдельный workspace с месячным лимитом расходов (около $40, выше программного бюджета $30) и API-ключ в нём; записать ключ в `.env.local`.
- [ ] Установить Node.js LTS (22+).
- [ ] По желанию: создать удалённый репозиторий и привязать его (`git remote add origin ...`).

## Настройка Supabase (этап 2, вручную)

1. **Таблица `users`.** Откройте Supabase Dashboard, затем SQL Editor и New query. Вставьте содержимое `supabase/migrations/0001_users.sql` и нажмите Run.
2. **Подтверждение e-mail.** На время пилота рекомендуется отключить: Authentication, затем Sign In / Providers, затем Email, переключатель «Confirm email». Встроенная почта Supabase отправляет всего несколько писем в час.
3. **Назначить администратора.** Зарегистрируйтесь на сайте, затем выполните в SQL Editor:

   ```sql
   update public.users set role = 'admin' where email = 'ваш@email';
   ```

## Таблицы и контент (этап 3)

1. **Таблицы.** В SQL Editor выполните `supabase/migrations/0002_content.sql`, как и `0001`.
2. **Контент.** Выполните `npm run import:content -- content/course.json`. Формат файла описан в [`content/README.md`](content/README.md).
3. **Проверка прав.** Выполните `npm run test:rls`. Скрипт создаёт двух временных учеников, проверяет, что они не видят чужие данные и скрытые поля задач, и удаляет их.

## ИИ-наставник (этап 5)

1. **Учёт расходов.** В SQL Editor выполните `supabase/migrations/0003_ai_usage.sql`.
2. **Ключ.** `ANTHROPIC_API_KEY` в `.env.local` (только сервер). Модели, цены и лимиты лежат в `src/config/ai.ts`.
3. **Попытки обхода.** `npm run ai:bypass` показывает 20 попыток, `npm run ai:bypass -- --run` отправляет их в API (около $0,10) и печатает ответы для ручной проверки.

Модель: наставник и проверка ответов работают на Claude Sonnet 5.5 (`src/config/ai.ts`). Системный промпт кэшируется (порог Sonnet 5.5 — 512 токенов); фактический эффект виден в `ai_usage.cache_read_tokens`.

## Баллы (этап 6)

В SQL Editor выполните `supabase/migrations/0004_points.sql`. Таблица баллов за задачу лежит в `src/config/points.ts`.

## Админ-панель (этап 7)

1. В SQL Editor выполните `supabase/migrations/0005_admin.sql` (вердикты проверки в журнале попыток и время последней активности учеников).
2. Админ-панель: `/admin` (роль `admin`). Разделы: дашборд и уведомление о бюджете ИИ, темы и задачи, ученики (блокировка, временный пароль, удаление), экспорт CSV.
3. Экспорт псевдонимизирован: вместо имени и e-mail код ученика `S-xxxxxx`. Свободный текст ответов и сообщений не изменяется, кроме маскировки телефонов и e-mail.
4. Тему или задачу, по которой есть данные учеников, удалить нельзя, только отредактировать.

## Файлы к ответам (этап 8)

1. В SQL Editor выполните `supabase/migrations/0006_attachments.sql`: создаются закрытое хранилище `answer-files` и таблица `attachments`.
2. Ученик прикрепляет до 3 файлов (JPG, PNG, PDF, DOCX, до 5 МБ). Браузер загружает их прямо в хранилище по одноразовым ссылкам, сервер проверяет тип по содержимому, удаляет из фото метаданные (в том числе GPS) и передаёт файлы в проверку ответа.
3. Потолок одной проверки с файлами — 25 000 входных токенов (около $0,05), см. `src/config/files.ts`.
4. Ученик видит и открывает только свои файлы; администратор видит все файлы в разделе «Файлы» и на странице ученика. Ссылки на файлы действуют 60 секунд.

## Курс: 34 темы (критическое и инженерное мышление)

1. В SQL Editor выполните `supabase/migrations/0007_engineering.sql`: тип задачи `analytical` переименовывается в `engineering`.
2. Один раз удалите три тестовые темы: `node --env-file=.env.local scripts/reset-sample-topics.ts` показывает, что будет удалено, а с `--run` удаляет темы, прогресс и файлы по ним и списывает баллы за эти задачи.
3. Загрузите курс: `npm run import:content -- content/course.json`. Условия задач взяты из таблицы заданий; готовые ответы не хранятся, из них составлены критерии проверки.

`content/sample-topics.json` больше не загружается в базу: по нему работают `ai:bypass` и `ai:scenarios`.

## Регистрация по кодам приглашения

1. В SQL Editor выполните `supabase/migrations/0008_invites.sql`.
2. В Supabase: Authentication → Sign In / Providers → выключите «Allow new users to sign up». Аккаунты создаёт сервер после проверки кода, поэтому публичным ключом обойти коды нельзя.
3. Админка → «Приглашения»: создайте коды и раздайте ученикам по одному. Код работает для одной регистрации; неиспользованный код можно удалить.

## Демо-ученики

`npm run demo:students -- content/private/demo-answers.json content/private/demo-report.json --run --max-usd=4` создаёт учеников test3, test4 и test5 (e-mail `testN@example.com`) и проводит их через все задачи с настоящими наставником и проверкой. test3 решает без ИИ, test4 задаёт наставнику один вопрос на задачу, test5 открывает две подсказки и пишет наставнику три раза. Ответы, отчёт и пароли лежат в `content/private/`, эта папка не попадает в git. Аккаунты не удаляются. Прогон 2026-10-08 стоил $1,67.

## Публикация (Vercel)

Сайт: https://logika-plus.vercel.app (проект `logika-plus`). Локальная и опубликованная версии работают с одной базой Supabase.

1. Один раз: `npx vercel login`, `npx vercel link --project logika-plus`, переменные из `.env.example` добавлены в Production через `npx vercel env add`.
2. Новая версия: закоммитьте изменения и выполните `npx vercel deploy --prod`. Файлы из `.vercelignore` (ключи, `content/private/`, таблицы) не загружаются.
   После публикации проверьте, что адрес сайта указывает на новую сборку: `npx vercel inspect logika-plus.vercel.app` (поле `url`). Если там старая сборка (так бывает после отката в панели Vercel), выполните `npx vercel promote <адрес новой сборки> --yes`.
3. В Supabase: Authentication → URL Configuration → Site URL = адрес сайта.

## Проверка с телефона

Запустите `npm run dev`, узнайте адрес компьютера в домашней сети (`hostname -I`, например `192.168.1.117`) и откройте на телефоне `http://192.168.1.117:3000`. Адреса `192.168.*.*` разрешены в `allowedDevOrigins` (`next.config.ts`); для другой сети добавьте её туда и перезапустите `npm run dev`.

## Скрипты

| Команда | Что делает |
| --- | --- |
| `npm run dev` | сервер разработки на http://localhost:3000 |
| `npm run build` | production-сборка |
| `npm run lint` | ESLint |
| `npm run typecheck` | проверка типов |
| `npm test` | тесты (Vitest) |
| `npm run import:content -- <файл>` | импорт тем и задач из JSON (`--dry-run` только проверяет файл) |
| `npm run test:rls` | проверка прав доступа на живой базе Supabase |
| `npm run ai:bypass [-- --run]` | 23 попытки обхода наставника и проверки, в том числе через файлы (`--run` тратит токены) |
| `npm run ai:scenarios [-- --run]` | ответы ИИ в обычных учебных ситуациях с ожидаемым поведением (`--run` тратит токены) |
